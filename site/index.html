A terminal app for Apache Iceberg tables

See the rest of the iceberg.

icelens shows what an Iceberg table is made of: its commits, the manifests and files each one points at, and the rows, as of any commit you pick.

  • Learn Iceberg. icelens --demo opens a table with five commits, and a guide beside every pane explains what the cursor is on.
  • Inspect your production tables. Point it at your catalog and see why a table has the files it has, what a commit changed, and what the rows were before it. It only reads.

Try it on the demo table: one command, nothing to configure.

uvx icelens --demo

What icelens shows

A query sees the tip. icelens shows the rest.

SELECT * FROM demo.orders183 rows. That is all a query says.
what icelens shows
  1. metadata.jsonthe table at one moment: schemas, specs, refs1
  2. snapshotsevery commit, and the one you are viewing4
  3. manifest list → manifestswhat that snapshot points at6
  4. data & delete fileswhat was live, then7
  5. rowsread as of the snapshot you pinned3
Why

What a query does not tell you.

Why the last write made three snapshots, which files a commit retired, what the schema was six versions ago. icelens shows each of these in a pane.

Pin a snapshot

Press Enter on a snapshot and every pane re-reads as of it: the schema it was written with, the files that existed then, the rows as of then.

u returns to the current snapshot.

4 Snapshots · demo.orders
1 │ append       +120 rows
2 │ append        +30 rows
3 │ overwrite    −12 test rows  ◀ Enter
4 │ append        +20 rows
5 ◆ append        +25 rows  current
every pane now answers as of 3

Ten panes, ten keys

Overview, Schema, Data, Snapshots, Commit, Manifests, Files, Partitions, Layout and SQL, on 1–9 and 0.

A guide rail

A rail under every pane explains whatever the cursor is on: the pane, the column, the value. g cycles it; --explain prints the same terms.

A sandbox to write in

The one place icelens writes. CREATE, INSERT, DELETE, and a ledger of what each commit did; --v3 adds deletion vectors, row lineage and MERGE.

Every pane, headless

--pane, --sql and --json print what a pane would show, for scripts and for CI. The JSON is a tested contract.

Manifests

What one snapshot points at.

The manifest list behind the current snapshot, one row per manifest: who added it, its rows, its sequence number and its partition spec. Two specs side by side here, because the last commit was written after partitioning by region.

The panes

One key each. All of them follow the pinned snapshot.

  • 1OverviewWhat metadata.json says: version, uuid, location, refs, properties, the metadata log.
  • 2SchemaThe viewed snapshot's schema, nested fields and field ids, identifier fields and partition transforms.
  • 3DataRows through DuckDB when it can attach, PyIceberg otherwise; a limit, a WHERE, row lineage on v3.
  • 4SnapshotsEvery commit, oldest first: the current one, its ancestors, anything off the chain.
  • 5CommitWhat one snapshot changed: the files it added and the files it retired.
  • 6ManifestsThe manifest list, one row per manifest, with partition ranges.
  • 7FilesEvery live file at that snapshot: data, position deletes, equality deletes.
  • 8PartitionsPartitions with their file and row counts.
  • 9LayoutThe pointer chain, indented: metadata → snapshot → manifest list → manifests → files.
  • 0SQLAny DuckDB SQL over the attached catalog, time travel included.
Install

One command.

It reads any Iceberg catalog PyIceberg can reach. Tested with Iceberg REST (Lakekeeper, Apache Polaris), Google BigLake and local SQL catalogs; see Platforms for the rest.

Install

With uv, or pipx.

uv tool install icelens
pipx install icelens
icelens --version

Open a catalog, or start with none

It finds the catalog this directory is configured for.

icelens                      # this directory's catalog
icelens demo.orders          # straight onto a table
icelens --uri http://localhost:8181/catalog --warehouse demo
icelens --demo               # a local catalog worth opening
